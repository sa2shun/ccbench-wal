\section{Proposal: Ayame}
\label{sec:design}

A frontier $F$ is a vector of per-shard log positions.  $F \fjoin F'$
denotes the element-wise maximum, $F \le F'$ holds iff $F[i] \le F'[i]$
for every shard $i$, and $\bot$ denotes the empty frontier whose
positions are all zero.  $D$ denotes the durable vector, where $D[i]$ is
the largest log position of shard $i$ that is known to be durable;
each $D[i]$ advances monotonically.

Ayame consists of worker-side functions that collect dependencies
during execution (Algorithm~\ref{alg:ayame-dep}), a worker-side commit
function that appends the log record and publishes the closed frontier
(Algorithm~\ref{alg:ayame-commit}), and committer-side functions that
return durable acknowledgments (Algorithm~\ref{alg:ayame-ack}).

\begin{algorithm}[t]
\caption{\bfseries Worker-Side Dependency Collection (Ayame)}
\label{alg:ayame-dep}
\begin{algorithmic}[1]
\Function{Begin}{$T$}
    \State $T.\dep \gets \bot$
\EndFunction
\Statex
\Function{ReadVersion}{$T, v$}
    \State add $v$ to $T$'s read set
    \If{$T$ is known read-only}
        \State \Return \Comment{SI read-only fast path}
    \EndIf
    \State $T.\dep \gets T.\dep \fjoin v.\wfr$ \label{ln:dep-read}
           \Comment{the writer of $v$}
\EndFunction
\Statex
\Function{OverwriteVersion}{$T, v$}
    \State add the new version to $T$'s write set
    \State $T.\dep \gets T.\dep \fjoin v.\wfr \fjoin v.\rfr$
           \label{ln:dep-write}
           \Comment{the writer of $v$ and its readers}
\EndFunction
\end{algorithmic}
\end{algorithm}

\begin{algorithm}[t]
\caption{\bfseries Worker-Side Commit Protocol (Ayame)}
\label{alg:ayame-commit}
\begin{algorithmic}[1]
\Function{Commit}{$T$}
    \State $T.c \gets$ commit timestamp assigned by SSN
           \label{ln:cstamp}
           \Comment{logical LSN}
    \If{\Call{SsnValidate}{$T$} fails}
        \State abort $T$; \Return
    \EndIf
    \If{$T$'s write set is empty} \Comment{read-only}
        \State \Call{Register}{$T.\dep, T$}; \Return
               \label{ln:ro-register}
               \Comment{Algorithm~\ref{alg:ayame-ack}}
    \EndIf
    \State $s \gets$ WAL shard owned by this worker
    \State $r \gets$ \Call{BuildRecord}{$T.c, T.\dep, T.\mathit{write\_set}$}
    \State $T.\lseq \gets$ \Call{Enqueue}{$\mathit{wal}[s], r$}
           \label{ln:enqueue}
           \Comment{append only; no flush, no wait}
    \State $F \gets T.\dep$; \quad $F[s] \gets \max(F[s], T.\lseq)$
           \label{ln:closed}
           \Comment{closed frontier}
    \ForAll{versions $v$ created by $T$}
        \State $v.\wfr \gets F$ \label{ln:pub-w}
    \EndFor
    \ForAll{versions $v$ read by $T$}
        \State $v.\rfr \gets v.\rfr \fjoin F$ \label{ln:pub-r}
               \Comment{monotone merge}
    \EndFor
    \State \Call{Register}{$F, T$}
           \label{ln:register}
           \Comment{durable ack deferred to the committer}
    \State \Return logical commit
\EndFunction
\end{algorithmic}
\end{algorithm}

\begin{algorithm}[t]
\caption{\bfseries Committer-Side Durable Acknowledgment (Ayame)}
\label{alg:ayame-ack}
\begin{algorithmic}[1]
\Statex \textbf{State:} durable vector $D$; per-shard waitlists $W[i]$
        ordered by required position
\Function{Register}{$F, T$}
        \Comment{atomic w.r.t.\ \textsc{OnDurableAdvance}}
    \State $T.\mathit{remaining} \gets 0$
    \ForAll{shards $i$ such that $F[i] > D[i]$}
        \State $T.\mathit{remaining} \gets T.\mathit{remaining} + 1$
        \State insert $(F[i], T)$ into $W[i]$ \label{ln:park}
    \EndFor
    \If{$T.\mathit{remaining} = 0$}
        \State \Call{Ack}{$T$}
               \label{ln:dur-check}
               \Comment{own record and all dependencies durable}
    \EndIf
\EndFunction
\Statex
\Function{OnDurableAdvance}{$i, d$}
        \Comment{called by flusher $i$ after \texttt{fdatasync}}
    \State $D[i] \gets d$
    \While{$W[i]$ is not empty and \Call{MinKey}{$W[i]$} $\le d$}
        \State $(\mathit{need}, T) \gets$ \Call{PopMin}{$W[i]$}
        \State $T.\mathit{remaining} \gets T.\mathit{remaining} - 1$
        \If{$T.\mathit{remaining} = 0$}
            \State \Call{Ack}{$T$} \label{ln:ack-ready}
        \EndIf
    \EndWhile
\EndFunction
\end{algorithmic}
\end{algorithm}

Algorithm~\ref{alg:ayame-dep} accumulates into $T.\dep$ the log
positions that must be durable before $T$ may be acknowledged: reading
a version makes $T$ depend on its writer
(line~\ref{ln:dep-read}), and overwriting a version makes $T$
additionally depend on the readers of the overwritten version
(line~\ref{ln:dep-write}).  Transactions known to be read-only skip
collection entirely.

In Algorithm~\ref{alg:ayame-commit}, the commit timestamp $T.c$ that
SSN assigns for validation doubles as the logical LSN of the log
record (line~\ref{ln:cstamp}); Ayame allocates no WAL-side global
sequence number.  The worker only enqueues the record to its own shard
(line~\ref{ln:enqueue}) and never calls \texttt{fdatasync} or waits
for durability.  The closed frontier $F$ extends $T.\dep$ with $T$'s
own log position (line~\ref{ln:closed}) and is published to the
versions $T$ wrote and read
(lines~\ref{ln:pub-w} and~\ref{ln:pub-r}), so that future transactions
inherit it through Algorithm~\ref{alg:ayame-dep}.

Algorithm~\ref{alg:ayame-ack} acknowledges $T$ once $F \le D$, i.e.,
once $T$'s own record and every record $T$ depends on are durable.
A transaction waits only on the shards whose durable position has not
yet reached its requirement (line~\ref{ln:park}); shards unrelated to
$T$ never delay its acknowledgment, unlike a global durable prefix.
Flushers require no algorithm of their own: each flusher owns one WAL
shard, writes the queued records as a single batch, calls
\texttt{fdatasync}, and invokes \textsc{OnDurableAdvance} with the new
durable position.
