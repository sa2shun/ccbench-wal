\subsection{Logging}
\subsubsection{P-WAL}

P-WAL~\cite{kamiya2017pwal} removes the single insertion point of a
shared write-ahead log by giving each worker thread its own log stream.
Algorithm~\ref{alg:pwal} shows the commit procedure.  A transaction first obtains its log
sequence numbers from a single monotonically increasing global counter
$L$ (lines~\ref{ln:pwal-rec} and~\ref{ln:pwal-clsn}); these numbers
define the global order in which records must be replayed during
recovery.  The worker then appends its redo records and a commit record
to its own stream, writes the stream, and makes it durable with
\texttt{fdatasync} (line~\ref{ln:pwal-sync}).  Because streams are
private, the writes of different workers proceed in parallel and never
contend on a shared log latch.

Acknowledgment, however, is governed by the \emph{global durable
prefix} $P$, defined as the largest $\ell$ such that every record whose
LSN is at most $\ell$ is durable.  A transaction $T$ may be acknowledged
only once $P$ reaches $T$'s commit LSN
(line~\ref{ln:pwal-wait}), which guarantees that every record ordered
before $T$ --- including records written by \emph{other} workers on
\emph{other} streams --- is already durable.

\begin{algorithm}[t]
\caption{\bfseries Per-Thread WAL Commit (P-WAL)}
\label{alg:pwal}
\begin{algorithmic}[1]
\State \textbf{Shared:} global LSN counter $L$; durable prefix $P$,
       the largest $\ell$ such that every record with $\mathrm{LSN}\le\ell$
       is durable
\Function{PwalCommit}{$T$, worker $w$}
    \For{each write $e \in T.\mathit{write\_set}$}
        \State append $\langle \textsc{FetchInc}(L),\, e \rangle$ to
               $\mathit{stream}[w]$
               \label{ln:pwal-rec}
               \Comment{global counter}
    \EndFor
    \State $T.\ell \gets \textsc{FetchInc}(L)$
           \label{ln:pwal-clsn}
           \Comment{commit LSN, global counter}
    \State append commit record $\langle T.\ell \rangle$ to
           $\mathit{stream}[w]$
    \State \Call{Write}{$\mathit{stream}[w]$};
           \Call{Fdatasync}{$\mathit{stream}[w]$}
           \label{ln:pwal-sync}
           \Comment{worker blocks on storage}
    \State \Call{AdvanceDurablePrefix}{} \Comment{recompute $P$}
    \While{$P < T.\ell$}
           \label{ln:pwal-wait}
           \Comment{global-prefix acknowledgment}
        \State \Call{AdvanceDurablePrefix}{}
    \EndWhile
    \State \Call{Acknowledge}{$T$}
\EndFunction
\end{algorithmic}
\end{algorithm}

% Problem of P-WAL
P-WAL is attractive because it removes the single-WAL insertion bottleneck by assigning transactions to multiple log streams.  However, combining P-WAL with SSN exposes three
problems.

\textbf{P1. Multiple Global Counter Accesses:~} First, P-WAL can introduce frequent global-counter accesses.  Even if the CC
layer already assigns a commit timestamp for SSN validation and serialization, the recovery layer may allocate a separate global LSN or maintain a global durable prefix.  This duplicates the ordering work already performed by the CC layer and adds shared-memory synchronization to the commit path.

\textbf{P2. Waiting for Data Transfer:~} Second, workers can spend a long time waiting around \texttt{fdatasync}.  P-WAL parallelizes log streams, but a transaction cannot be acknowledged until the corresponding durable condition is satisfied.  If worker threads wait directly
for log flushes or durable-prefix updates, storage synchronization and notification latency reduce the effective scalability of the CC protocol.

\textbf{P3. Total History:~} Third, global-prefix acknowledgment waits for log records that are unrelated to the transaction being acknowledged.  This rule is safe, but overly conservative:
if one WAL shard is slow, transactions on other shards may be delayed even when they have no dependency on transactions logged by the slow shard.  The opposite design point, local-only acknowledgment, avoids this delay but is unsafe.  If transaction $T$ reads a value written by transaction $U$, acknowledging $T$ before $U$ is recoverable may allow a crash recovery state that contains $T$ without the state on which $T$ depends.
